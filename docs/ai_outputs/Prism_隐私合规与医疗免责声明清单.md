# Prism 隐私合规与医疗免责声明清单

生成日期：2026-05-30
适用范围：Prism Metabolic Console 移动端优先 AI 代谢健康产品的内测、灰度和商业化前准备。
重要说明：本文是产品与工程执行清单，不构成正式法律意见；上线前应由法务、隐私合规负责人和医疗健康合规顾问复核。

## 1. 合规定位

Prism 当前应定位为健康管理、饮食记录、代谢风险提醒和生活方式建议工具，不应被描述为医疗诊断、治疗、处方、急救、疾病管理决策或医生/注册营养师替代工具。

产品处理的数据包括手机号、账号信息、身体参数、慢病/过敏信息、饮食记录、聊天内容、图片、健康指标、报告、设备会话、审计日志和可能的支付/订阅状态。这些信息接近或属于敏感个人信息，应按高保护等级设计。

## 3. 数据清单

| 数据类别 | 示例 | 敏感性 | 默认处理原则 |
|---|---|---|---|
| 账号身份 | 手机号、昵称、密码哈希、设备会话 | 高 | 最小化收集；手机号日志脱敏或哈希；密码只存哈希 |
| 健康档案 | 高血压、痛风、糖尿病、高脂血症、过敏 | 高 | 明示告知并取得同意；仅用于个性化风险提醒 |
| 身体参数 | 身高、体重、BMI、BMR、健康目标 | 中高 | 用于目标估算；不得宣传为医学评估 |
| 饮食记录 | 食物、份量、热量、钠、嘌呤、宏量营养 | 中高 | 用户确认后入库；估算字段需标识 |
| 聊天内容 | 用户问题、AI 回复、反馈、纠错文本 | 高 | 用于服务回复和质量改进；避免后台裸露敏感文本 |
| 图片上传 | 餐食照片、可能含 EXIF 或环境信息 | 高 | 限制类型/大小；清除 EXIF；避免长期保存原图 |
| 健康指标 | 血压、血糖、尿酸、血脂、腰围、体脂 | 高 | 仅做趋势和记录；异常值提示就医而非诊断 |
| 审计日志 | 登录、OTP、数据权利、AI 安全、知识决策 | 中高 | 保留必要字段；不写入原始手机号、原图、密钥 |
| 订阅状态 | FREE/PRO/COACH、mock checkout、取消记录 | 中 | 明确当前是否真实收费；支付接入前不得误导 |

## 4. 隐私政策清单

- [ ] 明确产品名称、运营主体、联系方式、投诉/撤回同意渠道。
- [ ] 分场景说明收集数据：注册登录、健康档案、饮食日志、拍照识别、语音/文本记餐、AI 聊天、健康指标、报告、反馈、设备会话、审计日志。
- [ ] 单独说明敏感个人信息：慢病/过敏、健康指标、饮食记录、图片、聊天中主动提供的健康信息。
- [ ] 说明处理目的：账号安全、饮食记录、代谢风险提醒、AI 回复、报告生成、离线同步、纠错和安全审计。
- [ ] 说明第三方处理：短信服务商、火山方舟/豆包模型、云数据库/托管平台、未来支付服务商；不得暴露密钥或内部 endpoint。
- [ ] 说明数据保存期限：账号有效期内、用户删除后、注销后、备份和审计日志的保留边界。
- [ ] 说明用户权利：访问、更正、复制/导出、删除、注销、撤回同意、投诉。
- [ ] 说明儿童和特殊人群：未成年人使用需监护人同意；孕期、儿童、肾病、用药等特殊情况应咨询医生。
- [ ] 说明安全措施：传输加密、访问控制、日志脱敏、上传校验、设备会话撤销、审计。
- [ ] 说明政策更新机制：版本号、生效日期、重大变更提示和重新同意。

## 5. 用户协议清单

- [ ] 用户承诺提供真实、准确、必要的健康和饮食信息；错误输入会影响建议质量。
- [ ] 用户不得把 Prism 用于急救、诊断、治疗、处方、药物调整或替代医生决策。
- [ ] AI 识别、营养估算、风险提醒和报告均为参考，需用户核对并自行决定是否采纳。
- [ ] 对高风险症状、严重过敏反应、血糖/血压急剧异常、胸痛、呼吸困难等情况，协议应要求立即寻求医疗帮助。
- [ ] 明确禁止上传违法、侵权、含他人隐私或与服务无关的图片/文本。
- [ ] 明确账号安全责任：验证码、密码、设备会话管理，发现异常应撤销设备并联系客服。
- [ ] 明确服务变更、暂停、维护、第三方服务不可用、模型失败时的处理。
- [ ] 如有订阅，必须区分 mock/测试权益和真实收费权益；真实支付前补齐支付协议、退款和发票规则。

## 6. 医疗免责声明清单

### 6.1 必须表达

- Prism 不是医疗机构，产品输出不构成医学诊断、治疗建议、处方、用药调整或急救指导。
- Prism 提供的是饮食记录、营养估算、代谢风险提醒和生活方式参考。
- AI 或规则输出可能因用户输入不完整、食物识别误差、知识库覆盖不足、模型错误而不准确。
- 用户有慢病、过敏、孕期、儿童、肾病、肝病、进食障碍、术后恢复、正在用药或异常症状时，应咨询医生或注册营养师。
- 任何药物、治疗计划、检查结果解释和疾病诊断，应以医生意见为准。

### 6.2 建议短文案

> Prism 提供饮食记录、营养估算和健康管理参考，不提供医疗诊断、治疗、处方或急救服务。AI 输出和营养数据可能存在误差，请在采纳前自行核对；如有疾病、过敏、用药或异常症状，请咨询医生或注册营养师。

### 6.3 场景化放置

- 注册/首次进入：完整免责声明入口。
- 聊天页输入框附近：短提示“AI 回复仅供健康参考，不能替代医生”。
- 拍照识别结果：提示“识别和营养值为估算，请确认后再写入日志”。
- 候选确认页：展示置信度、估算字段、本地规则命中和“用户确认”按钮。
- 报告页：报告仅供个人健康管理，不作为诊断或治疗依据。
- 高风险关键词：药物、急症、孕期、儿童、肾病、严重过敏，应展示强提醒并引导就医。

## 7. AI 免责声明清单

- [ ] AI 内容显式标识为 AI 生成或 AI 辅助生成。
- [ ] 拍照识别、份量、热量、钠、嘌呤、宏量营养标识为估算值。
- [ ] AI 候选必须由用户确认后写入饮食日志。
- [ ] 用户修改候选食物、份量、食材或烹饪方式后，必须重新评估。
- [ ] 本地规则命中 AVOID、LIMIT、过敏或显式忌口时，AI 不得改写成“可以放心吃”。
- [ ] AI 回复提供反馈入口：有帮助、无帮助、有风险、识别错误、知识缺口。
- [ ] 运营侧有 AI 审计：fallback 状态、是否调用云端、阻断原因、风险反馈状态。
- [ ] 对用户明确询问诊断、药物、治疗方案时，AI 应拒绝给出个体化医疗建议并引导就医。

## 8. 数据导出、删除和注销清单

| 能力 | 必做项 | 验收 |
|---|---|---|
| 数据导出 | 导出用户资料、健康档案、饮食、聊天、健康指标、报告、反馈等用户范围内数据 | 文件不含其他用户数据；有导出审计 |
| 饮食/健康数据删除 | 明确删除范围、不可恢复提示、二次确认 | 删除后 API 和前端不再显示 |
| 账号注销 | 撤销设备会话、删除或匿名化可删除数据、保留必要审计 | 注销后不能登录；安全审计存在 |
| 备份保留 | 说明备份中删除的滞后和周期 | 隐私政策中透明披露 |
| 客服处理 | 建立人工处理 SLA 和身份核验 | 不通过聊天或 issue 直接索要敏感数据 |

## 9. 上传安全清单

- [ ] 前端限制可选文件类型、大小，并展示上传进度、取消和重试。
- [ ] 后端验证 Content-Type、文件头、实际可解码性、字节大小和像素预算。
- [ ] 上传图片进入模型前清除 EXIF，并重新编码。
- [ ] 不在日志、审计、错误消息、反馈后台中保存原始图片、EXIF、密钥或临时 URL。
- [ ] 对失败原因做用户可理解的提示，例如“图片过大”“格式不支持”“识别失败，请手动记录”。
- [ ] 如未来长期保存图片，需新增保存目的、保存期限、访问权限、删除机制和用户单独同意。
- [ ] 上传异常峰值进入运营监控，避免被用作恶意文件探测入口。

## 10. 短信验证码风险清单

- [ ] 生产环境禁止 `OTP_PROVIDER=dev`，验证码不得通过响应体返回。
- [ ] 同手机号、同 IP、同设备、同账号维度设置发送频控。
- [ ] 验证失败达到阈值后锁定，并写入审计。
- [ ] 返回文案避免用户枚举，例如不明确暴露手机号是否注册。
- [ ] 日志中手机号使用哈希或脱敏格式，不写入验证码明文。
- [ ] 短信供应商密钥只放环境变量或密钥管理系统，不提交仓库。
- [ ] 供应商回调需要签名校验或可信来源校验。
- [ ] 建立短信成本告警和异常发送量监控。
- [ ] 密码重置、验证码登录、注册流程的频控策略分别测试。

## 11. 内测前合规验收

- [ ] 新用户能在注册前打开用户协议、隐私政策、医疗免责声明、AI 免责声明。
- [ ] 未勾选协议时不能注册；协议版本号记录在用户同意记录中。
- [ ] 聊天、拍照、报告、健康档案均有场景化短免责声明。
- [ ] AI 识别结果不自动变成正式饮食记录，用户需确认。
- [ ] 用户可导出数据、删除数据、注销账号。
- [ ] 生产配置不允许 dev OTP、默认 JWT secret、localhost API、通配 CORS、占位 AI 模型。
- [ ] 后台和日志不暴露原始手机号、验证码、密钥、模型 endpoint、原始图片。
- [ ] 高风险健康问题可触发保守拒答和就医引导。
