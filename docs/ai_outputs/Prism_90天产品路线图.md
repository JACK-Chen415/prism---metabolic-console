# Prism 90天产品路线图

生成日期：2026-05-30
适用阶段：功能型 MVP / Alpha+ 到真实用户小规模内测
产品定位：移动端优先的 AI 代谢健康记录、风险提醒与生活方式建议产品，不提供医疗诊断、治疗、处方或替代医生/注册营养师的服务。

## 1. 路线图原则

- 移动端优先：优先优化手机浏览器/PWA 视角下的首页、记餐、拍照、聊天、离线队列和设置路径。
- 用户确认优先：AI 图片识别、语音解析、文本记餐和健康建议均应在关键动作前让用户确认，不允许高风险候选静默入库。
- 本地规则优先：高血压、痛风/高尿酸、2 型糖尿病、高脂血症、过敏和显式忌口类判断先过本地知识库；AVOID、LIMIT、过敏命中时云端 AI 不得放宽结论。
- 健康边界清晰：所有输出限定为健康管理、饮食记录和生活方式参考；遇到急性症状、用药调整、诊断诉求、孕期/儿童/肾病等特殊场景，引导咨询医生。
- 合规和审计前置：隐私政策、用户协议、医疗免责声明、AI 免责声明、数据导出/删除、上传安全、短信验证码安全和审计日志是内测前置条件。

## 2. 90 天目标

90 天结束时，Prism 应达到“小规模真实用户内测可控开放”状态：

- 20-60 名真实用户可在手机端完成注册、健康档案、拍照/语音/手动记餐、AI 问答、报告查看和反馈提交。
- 高风险健康建议有本地规则约束、输出后复核、免责声明和用户反馈入口。
- 用户可查看隐私/协议/免责声明，可导出数据、删除数据、注销账号。
- 运营侧可查看灰度就绪状态、AI 安全反馈、知识库缺口、上传/短信/登录风险和关键审计记录。
- 不上线真实收费，不宣传诊断治疗能力，不进入医疗器械或互联网诊疗表达。

## 3. 优先级定义

| 优先级 | 定义 | 90 天处理方式 |
|---|---|---|
| P0 | 内测安全、合规、账号和高风险健康输出的阻断项 | Day 1-30 必须完成或明确降级关闭 |
| P1 | 影响真实用户连续使用、留存和反馈质量的关键体验项 | Day 31-60 完成主要闭环 |
| P2 | 增强商业化验证、增长和长期产品力的项目 | Day 61-90 做可验证原型或灰度开关 |

## 4. 阶段安排

| 阶段 | 时间 | 主目标 | 退出标准 |
|---|---:|---|---|
| Phase A | Day 1-15 | 安全与合规封版 | 法务/产品文案入口齐全；高风险 AI 输出有复核；生产配置 gate 可拦截明显错误 |
| Phase B | Day 16-30 | 内测前可用性封版 | 手机端核心路径无明显阻断；短信、上传、数据权利、审计和反馈流程可演示 |
| Phase C | Day 31-45 | 记录体验和知识库补强 | 常见中国饮食覆盖提升；低置信度候选需显式确认；离线队列可解释 |
| Phase D | Day 46-60 | 报告、反馈和运营闭环 | 周/月报告、AI 反馈、知识缺口、管理台初步可用 |
| Phase E | Day 61-75 | 小规模真实用户试点 | 完成第一批用户任务脚本，沉淀问题池和安全事件清单 |
| Phase F | Day 76-90 | 内测扩容准备 | 指标复盘、风险修复、下一轮商业化 MVP 范围确认 |

## 5. P0 路线：安全内测封版

| ID | 切片 | 主要范围 | Codex 执行颗粒度 | 验收口径 |
|---|---|---|---|---|
| P0-01 | 合规文档入口复核 | 注册、设置、聊天、拍照、报告页的用户协议、隐私政策、医疗免责声明、AI 说明 | 逐页面检查入口、跳转、勾选、版本号和空状态 | 新用户注册前可查看并同意；AI/健康页面可见边界提示 |
| P0-02 | 短信验证码生产门禁 | OTP provider、频控、失败锁定、审计、生产禁止 dev debug_code | 后端配置 gate、接口错误态、灰度文档逐项验收 | 生产配置下不回传验证码；同手机号/IP/设备过频会被限制 |
| P0-03 | AI 输出后规则复核 | AI 聊天、图片识别、语音/文本候选确认 | 在云端输出后抽取食物/建议并重新过本地规则；冲突时改写或阻断 | AVOID/LIMIT/过敏规则不被云端回复放宽 |
| P0-04 | 高风险候选强确认 | IntakeConfirmationSheet、后端 intake 确认接口 | 低置信度、规则不足、特殊人群、高风险食物禁止自动确认 | 用户编辑后必须重新评估；确认前显示估算来源和风险 |
| P0-05 | 上传安全和移动端失败态 | 相机页、聊天图片上传、后端 upload_security | 补齐大小、MIME、文件头、像素、EXIF、进度、取消、重试、错误提示 | 恶意/超限图片被拒绝；不在日志暴露原图或敏感 EXIF |
| P0-06 | 数据权利闭环 | 设置页、account API、导出/删除/注销、审计 | 检查导出内容、删除范围、二次确认、失败恢复、审计记录 | 用户可自助导出、删除数据、注销；高危操作有确认和日志 |
| P0-07 | 生产配置与灰度 gate | `/api/ready`、admin readiness、前端 VITE_API_URL | 明确红/黄/绿规则，禁止默认密钥、本地 API、通配 CORS、占位模型 | 灰度前可一键判断配置风险，不暴露密钥或模型 ID |
| P0-08 | 移动端核心路径冒烟 | 登录、首页、记餐、聊天、拍照、档案、设置 | 以 375px/390px/430px 宽度手工或自动截图走查 | 无按钮遮挡、文本溢出、关键流程断路 |
| P0-09 | 安全反馈入口 | AI 消息反馈、识别纠错、知识缺口反馈 | 用户可标记“有帮助/无帮助/有风险”，可提交纠错文本 | 运营侧可筛选 open/reviewed/closed，审计不暴露原始手机号 |

## 6. P1 路线：真实用户连续使用

| ID | 切片 | 主要范围 | Codex 执行颗粒度 | 验收口径 |
|---|---|---|---|---|
| P1-01 | 高频中国饮食知识库扩容 | seed foods/rules/sources、知识校验测试 | 每批 20-30 个食物/菜品，带别名、过敏、钠/脂肪/嘌呤/升糖风险标签 | 新增食物可被文本/语音/图片候选匹配，并有规则来源 |
| P1-02 | 快速记餐体验 | 日志页、聊天快捷记餐、常吃食物、复制昨日 | 小切片增加“常吃”“复制上一餐”“最近记录” | 手机端 30 秒内可完成一条手动记录 |
| P1-03 | 候选编辑增强 | 食材、调料、烹饪方式、多人份拆分 | 先做 UI 字段，再做重新评估和写入映射 | 用户可修正 AI 识别错误并触发重新评估 |
| P1-04 | 离线队列可解释 | IndexedDB 队列、设置队列检查器、日志卡状态 | 明确 PENDING/SYNCED/FAILED/CONFLICT 文案和操作 | 用户知道哪些记录未同步，可重试或丢弃本地草稿 |
| P1-05 | 健康指标手动趋势 | 体重、血压、血糖、尿酸、腰围、血脂 | 先实现手动录入和最近趋势，不接真实设备 | 报告和首页可引用最近指标，但不做诊断结论 |
| P1-06 | 周/月报告产品化 | ReportsView、reports API、CSV/JSON 下载 | 优化目标对比、风险备注、免责声明、历史列表 | 用户能理解一周饮食趋势和下一步建议 |
| P1-07 | AI 会话管理和偏好 | ChatView、session API、assistant preferences | 会话列表、删除、风格偏好、干预强度持久化 | 切换会话不丢历史；偏好不改变安全边界 |
| P1-08 | 运营审查台轻量化 | AdminView、feedback、knowledge audit、release readiness | 过滤器、状态流转、只展示脱敏字段 | 内测问题可按风险、知识缺口、AI 错误定位 |
| P1-09 | 前端自动化最小集 | contract tests、Playwright/截图冒烟 | 覆盖登录、记餐、聊天、拍照上传失败态、设置数据权利 | 每次灰度前可复跑，不替代人工安全审查 |

## 7. P2 路线：商业化验证和扩展

| ID | 切片 | 主要范围 | Codex 执行颗粒度 | 验收口径 |
|---|---|---|---|---|
| P2-01 | 内测指标面板 | activation、D1/D7、记餐频次、确认编辑率、AI 风险反馈 | 先用后端聚合或导出，不引入侵入式埋点 | 可回答“用户是否真的连续记录” |
| P2-02 | 知识库审核工作流 | draft/reviewed/published、来源、版本 | 数据模型或管理台原型，先不做复杂 CMS | 规则上线前可追溯审核人、版本和来源 |
| P2-03 | 付费权益灰度 | FREE/PRO/COACH、mock billing、真实支付准备清单 | 保持 mock，不真实扣费；补齐权限边界和文案 | 用户不会误以为已真实支付；运营可验证套餐价值 |
| P2-04 | PWA 安装和离线增强 | manifest、service worker、离线提示 | 只缓存静态资源和安全可缓存数据 | 手机端可安装；无网时边界提示明确 |
| P2-05 | 设备接入预研 | HealthKit/Google Fit/体脂秤/血糖仪 provider | 保持 provider abstraction 和 mock 数据 | 不承诺实时医疗监测，只验证数据流 |
| P2-06 | 营养师/教练协作原型 | COACH plan、报告分享、用户授权 | 先做权限和授权文案，不开放公开市场 | 用户明确授权后才分享数据 |
| P2-07 | 特殊人群保守策略 | 孕期、儿童、肾病、用药、急症关键词 | 本地规则模板和 AI 拦截文案 | 高风险问题引导就医，不给个体化处方建议 |
| P2-08 | 商业化 MVP 决策包 | 指标复盘、用户访谈、风险清单、下一阶段路线 | 输出文档和 issue 列表 | 明确是否进入公开灰度、原生 App 或机构合作 |

## 9. 明确暂不做

- 不做疾病诊断、用药调整、治疗方案、处方建议。
- 不把 AI 识别的食物和营养估算描述为精确检测结果。
- 不在未完成支付网关签名、幂等、发票、退款和审计前接真实扣费。
- 不在未完成医疗监管路径评估前使用“治疗”“临床诊断”“医生替代”等表达。
- 不在未获得用户明示同意前向营养师、机构或第三方共享健康数据。

## 10. 90 天验收清单

- [ ] 手机端注册、登录、健康档案、记餐、拍照、聊天、报告、设置全路径可用。
- [ ] AI 相关输出带“估算/参考/需确认”提示，高风险输出可被本地规则阻断。
- [ ] 用户可查看并同意用户协议、隐私政策、医疗免责声明和 AI 免责声明。
- [ ] 数据导出、数据删除、账号注销有二次确认和审计日志。
- [ ] 上传安全、短信验证码、生产配置、CORS、密钥、模型配置有灰度 gate。
- [ ] 运营侧可查看 AI 风险反馈、知识缺口、账号安全、数据权利和灰度 readiness。
- [ ] 首批真实用户内测完成，输出指标复盘、用户反馈和下一阶段 backlog。
