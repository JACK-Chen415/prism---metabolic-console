# Prism 竞品差距报告（首版）

生成日期：2026-06-08

> 说明：基于仓库现有文档与当前产品实现进展，做第一版竞品差距梳理；仅列产品差距，不涉及代码修改。

| 当前 Prism 能力 | 对应的竞品模式 | 还缺/不同的部分 | 对留存/商业化的重要性 |
|---|---|---|---|
| 已有本地候选复核台、低置信度强确认、影响预览、替代建议 | MyFitnessPal 的 Meal Scan / 可编辑入日志流程 | 仍偏“单次确认”，缺少更强的日常高频工作流入口、批量处理和更顺滑的连续记餐体验 | 记餐越省力，日常打开频次越高；这是最直接的留存基础 |
| 已支持 favorites、recent meals、quick-copy、手动日志 | MyFitnessPal 的 remembered meals / 常用餐快捷复用 | 缺少更完整的“个人常吃库”分层：收藏、模板、历史复用、场景化建议还不够细 | 降低重复输入成本，能显著提升长期使用和付费意愿 |
| 已有条目确认前的本地规则校验与风险提示 | Cronometer 的条码优先 + 更可审计的营养录入 | 还没有成熟的条码扫描、营养标签 OCR、个人食品沉淀链路 | 包装食品是高频场景；不覆盖就会流失大量真实记录需求 |
| 已有 7 日趋势、报告中心、首页风险摘要 | Noom / Levels 的每日反馈与进度面板 | 反馈仍偏“看结果”，缺少更强的每日目标、行为引导、任务完成感和连续打卡机制 | 让用户每天有事可做，才能形成习惯和订阅型留存 |
| 已有“今日代谢控制台”雏形、风险摘要、下一步建议 | Levels-style metabolic console | 还没有足够像“控制台”的核心首页：缺少明确优先级、状态解释、单日行动闭环 | 首页如果只像入口页，用户很快就会流失；控制台感更利于日活 |
| 已有 7 天代谢微实验模板 | Noom 的课程/挑战 / Levels 的稳定性挑战 | 还缺更丰富的实验库、个性化编排、完成后复盘和结果故事化呈现 | 小目标更容易完成，也更容易转化为 PRO/Coach 付费理由 |
| 已有个人纠错到知识库闭环、别名沉淀、删除个人条目 | MyFitnessPal / Cronometer 的个人食品库 | 还缺对“个人知识资产”的更强可见性：用户不知道自己累计省了多少时间、提升了多少准确率 | 让用户感觉“越用越聪明”，能增强粘性和迁移成本 |
| 已有共享用餐与家庭份量拆分 | MyFitnessPal 的共享日志/餐食复制 | 仍偏一次性分享，缺少更稳定的家庭成员协作、共同管理、场景化分摊 | 家庭/伴侣场景会显著提高绑定度，也更利于裂变和续费 |
| 已有健康指标手工录入、报告、风险摘要 | Levels 的代谢指标联动 | 还没有 CGM / 设备联动，也没有“多信号融合”的强感知反馈 | 设备联动通常是高价值订阅场景，缺失会压低高客单价空间 |
| 已有安全护栏、合规文档、审计和灰度门禁 | Noom / 高合规健康产品的基础要求 | 还缺面向商业化的更清晰分层权益、教练/专家工作流、运营看板与转化漏斗 | 没有明确的商业分层，功能再好也难形成可持续收入 |

## 结论

Prism 已经具备“AI 原生、重安全、可审计”的底座，但和 MyFitnessPal、Cronometer、Noom、Levels 这类成熟产品相比，主要差距不在单点识别能力，而在**高频使用习惯、个人食品资产、包装食品录入、每日控制台、行为挑战、家庭协作、设备联动和商业化分层**。

优先级上，建议先补：
1. 包装食品扫码/OCR
2. 更强的首页代谢控制台
3. 个人食品库与纠错复用
4. 7 天微实验与打卡闭环
5. 共享用餐/家庭份量拆分
